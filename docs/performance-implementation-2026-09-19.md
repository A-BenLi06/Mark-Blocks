# RichEditBox 保留架构性能优化

本次保留 Windows 8.1 / Windows Phone 8.1、RichEditBox、Markdig 0.15.5 和 WebView。修改应用实现，没有迁移平台或更换输入控件。

## 已实施

- **输入调度**：普通输入使用 180ms 起步的静默期；25 万字符以上起步 450ms，200 万字符以上起步 900ms，并根据上一轮耗时调整，上限 1500ms。隐藏预览时，普通输入不再触发全文快照/解析；保存、切标签、挂起和显式刷新仍会同步缓冲。
- **取消旧工作**：输入、设置刷新和离开页面使旧任务失效；后台解析前后、分块输出期间检查取消。只有一个解析任务执行，后续只追赶最新请求。Markdig 的单次 Parse 本身没有被改造成可中断解析器。
- **文档读取**：读入后在后台统一换行；已经规范化的文本复用原字符串。装载 RichEdit 前关闭旧文档撤销记录，在批量显示更新中设置文本和默认格式；Windows 首次语法着色延后，优先让编辑器显示。
- **文本/保存**：使用单次规范化扫描，去掉连串全文 Replace；保存的换行和缩进加工在后台完成。同一文档写入串行化；保存期间的新原生输入或新模型版本不会被旧保存清除 dirty。文件选择器返回后保存捕获的原文档。
- **自动保存**：输入不再无限重置保存倒计时，持续写作也会到达保存时点；自动保存失败保留 dirty，并写调试日志。未命名文档仍需要另存为。
- **高亮**：范围硬上限 8192 字符；相同范围、文本和颜色复用结果；着色循环采用约 8ms 的软预算，较复杂正则有超时。非空选区不再整段改色，也不再主动 SetRange 恢复光标。高亮通知被隔离，不触发解析和 dirty。
- **撤销**：成功撤销后复用已读到的文本，省去一次额外全文读取；不立即重新着色。当存在 redo 历史时跳过着色，避免格式变更破坏 redo 分支。
- **后台输出**：图片地址处理、HTML 增强、补丁生成和 Base64 编码放在后台；设置和图片基路径在启动任务时捕获。UI 不再每轮拼接完整 HTML。
- **分块内存**：渲染 StringBuilder 逐块复用，不再累计整篇中间输出；用源区间计数行号，不复制每块 Markdown 源文。完整 HTML 仅需要时生成。
- **大纲**：标题到顶层块的定位改成二分查找；没有标题时不再无条件拆分全文执行备用正则扫描。
- **预览补丁**：Windows 与 Phone 使用同一协议，支持插入、删除、替换和空文档。正文比较不包含行号/索引；保留相同前后缀节点，等块数时还保留变化区域之间的节点。一次桥接批量提交，成功 ACK 后才推进缓存；块数不一致时执行一次全量恢复。
- **滚动**：保留可见块作为插删时的滚动锚点；视口附近块用二分定位，图片仅遍历邻近块和已激活图片，避免滚动时枚举全文所有块/图片。
- **重处理**：公式、图表、高亮继续延迟处理，块数预算叠加耗时预算。超过 5 万字符的代码块保留完整原文，但跳过语法高亮和行号增强，避免巨型代码块拖住预览。
- **首次资源**：纯文本预览不再嵌入 Mermaid、KaTeX 和代码高亮脚本；首次出现相应内容时加载，并在当前页面后续使用中复用。补丁及增强函数在骨架中定义一次，不再每次输入传输整套函数。
- **预览一致性**：纯写作切回预览会请求最新解析；文本版本和刷新请求版本共同阻止旧结果提交；正确处理 lazy 图片的 `data-src`，而非只规范化占位图 URL。

## 验证记录

- 使用本机 MSBuild 14.0 / Windows 8.1 SDK，Windows x86 Release 和 Phone ARM Release 均构建并生成包成功；构建关闭包签名，没有部署或发布。
- `tests/PerformanceRegression` 直接编译生产的渲染器、补丁、规范化、设置和保存代码，只替换 WinRT OS 边界。使用本地 Markdig 0.15.5；测试工程的 .NET 10 仅用于桌面运行测试，不改变应用目标。
- 24 个检查及额外 1000 组随机补丁重建通过，涵盖空文档、段落增删、远距离替换、源行号漂移、引用链接、重复标题、取消、按需库加载、保存并发和写入期间继续编辑。
- 使用已有 Playwright + Edge 的独立 HTML 测试页，验证实际 C# 生成的骨架和补丁。Browser 插件不可用；未增加应用或仓库的 npm 依赖。
- 浏览器检查通过：插删前后未变节点对象保持一致；失配不修改 DOM；清空和恢复正常；代码高亮、KaTeX、Mermaid 均出现；没有页面或控制台错误。测试页为相同的包内字体提供独立文件目录。
- 在构造的 10000 段落场景，单次邻近块查询共 86 次几何读取。该数字说明测试场景中的扫描工作量，不能转换成真机 FPS 或输入延迟。
- 预览截图覆盖 1100×760、390×760，产物在测试的 `artifacts/` 中，已从版本控制排除。

## 仍需真机确认的边界

### 2026-09-20：拼音停顿与新行输入保护

后续反馈指出问题也发生在有停顿的拼音输入中。按键是否仍按住不足以表示 IME 是否结束：旧逻辑停顿 650ms 后会对可见区域重置颜色、重新着色并更新插入点格式。此路径可能干扰候选词尚未提交时的原生排版，但目前没有目标机剖析数据证明它是全部停顿的来源。

本机 Windows 8.1 SDK 的 RichEditBox 不提供 TextCompositionStarted/Ended 事件。因此采取保守策略：编辑器持有焦点时，共享着色器和两端页面均不执行自动格式修改，保留待着色标志，LostFocus 后补做。已有颜色保留，新增内容的语法色可能延后到离开编辑框后更新；主题切换也遵循此保护。后台预览仍保留，基本等待时间由 180ms 提高至 700ms，中/大文档为 900/1200ms，并保留耗时反馈上限 1500ms。KeyDown 和 SelectionChanged 也记录活动，不能只根据 TextChanged 判断空闲；Windows 预览滚动同步同样等待 700ms。

这不是可靠的 IME 组合状态检测：较长选词停顿期间仍可能进行只读快照和预览处理。没有增加 Windows 10 API，也没有停止自动保存。Windows x86、Phone ARM Release 构建通过；既有 31 项检查和 1000 组随机用例通过，但不覆盖原生 IME。目标机需复验新行开头输入、候选框停留超过一秒、选词提交、短暂停顿续写和离开编辑框后的补色。

### 2026-09-20：双栏长按输入期间的工作避让

针对按住数字键不松手、双栏且关闭打字机模式的卡顿反馈，检查发现 Windows 滚动事件的最终帧会直接调用 WebView 脚本，且着色计时器执行前没有复核输入空闲时间。现在滚动事件只入队，经计时器合并；最近 180ms 有输入或编辑器按键仍按下时暂缓同步。两端解析和着色均检查当前键盘状态，覆盖首次按下到系统开始重复输入的间隙；着色还检查 650ms 输入静默期。按键状态由 CoreWindow 查询，焦点离开编辑器后不再阻挡后台工作，不依赖一定送达的 KeyUp。打字机居中与着色后的滚动恢复跳过不足 1 DIP 的无效位移。

Windows x86 / Phone ARM Release 构建和既有 31 项回归检查、1000 组随机补丁用例通过。这些检查不模拟原生键盘和 RichEdit 布局，因此尚不能证明用户报告的三次停顿均已消除；需在同一文档位置复验。自动保存的周期和持久化保障保持原有行为。

### 2026-09-20：正常取消的调试器异常修复

连续输入会取消旧预览。原实现通过 `ThrowIfCancellationRequested` 退出后台任务，Windows 和 Phone 的计时器虽已捕获 `OperationCanceledException`，调试器仍可能在抛出或跨异步边界传播时中断。现在正常取消返回 `null`（表示丢弃整次结果），两端页面显式跳过提交；解析前后、块渲染中及目录提取后检查取消，不发布半成品。真正渲染失败仍传播到原错误处理路径。Markdown 整体解析本身仍不能中途抢占。

回归验证通过 31 项检查及 1000 组随机补丁用例，新增覆盖预先取消、空文本取消、首/中/末块取消、取消后新任务成功、真正错误传播，并监听 first-chance exception 确认这些正常取消没有抛出取消异常。Windows x86 / Phone ARM Release 构建均通过；仍需在目标机调试器中复验连续输入、切换文档及离开页面。

没有宣称实际 Windows 8.1 / Phone 输入延迟或内存下降了某个百分比。现代 Edge 中的预览验证不能替代旧 WebView、原生 RichEdit、微软拼音/注音、触摸选择和软键盘的验收。

RichEdit 仍全文驻留，SetText 和需要时的 GetText 仍有随文件增长的成本。后台仍使用完整 Markdown AST，以保持跨段引用、脚注、列表等语义。DOM 仍全文驻留，本次优化的是差量更新、附近内容查询和延迟增强，没有贸然加入会改变全文选择、搜索和复制行为的 DOM 窗口化。

高亮预算是软预算：单个原生格式调用、正则或第三方图表渲染不能在任意指令点中断。密集文档可能只显示部分语法着色；redo 历史存在时着色暂停。原生格式记录仍可能占用撤销历史，现有跳过格式记录的循环仍保留，尚未用未经验证的原生接口禁用格式撤销。

首次引入一种重内容会重建一次骨架以加载缺少的库。多个远距离插删导致块数变化时，当前算法可能替换较宽的中间区域；等块数的远距离修改则分别更新。超大单块（长列表、表格、复杂图表）仍可能成为单次布局/第三方渲染热点。

推荐目标机验收：1/5/20MB 文章和超长单行，连续中文输入/停顿续打、大段粘贴、Ctrl+A、撤销重做、滚动、首段插入、保存中输入、切标签、挂起恢复。若这些测试仍指向 RichEdit 本身的布局成本，再评估进一步降级或输入后端替换。
